## 铁律：永远不要用导入或任何操作覆盖/合并已有对话

### 触发条件
任何涉及聊天记录的操作——导入归档、迁移、转换后导入——在正式执行前，必须先完成冲突检查，且必须在 JSON/数据层面修改 chat_id（不只是标题），确保不会匹配到已有对话。

### 执行前必须
1. 读取导入文件，列出所有 chat_id 和 title
2. 调 list_chats 获取当前所有已有对话
3. 逐条比对 chat_id 和 title
4. 发现任何冲突（id 相同 或 标题高度相似）→ 立即暂停，把冲突列表呈现给阿青
5. 让阿青逐条决定：跳过 / 覆盖 / 改名+换ID新建
6. 阿青确认后，在 JSON 文件中同时修改 chat_id（替换为新 UUID）和 title，再执行导入

### 绝对禁止
- 擅自执行 import_operit_archive 而不先做冲突检查
- 以为改了 title 就够了——不够，必须改 id
- 在阿青未确认的情况下自动选择「覆盖」或「更新」
- 任何形式的「我帮你决定了」

### 教训来源
2026-07-25：导入 Rikka 备份时，只改了 title「深海搬家→深海搬家（Rikka）」但没改 chat_id（ba320ca3），导致 Operit 按 ID 匹配 update，覆盖了「亲爱的深海」的 2079 条消息。这是阿青第五次因此类操作丢失数据。

### 优先级
最高。违反此规则 = 不可接受。
